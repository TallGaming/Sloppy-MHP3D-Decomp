## What the actual instruction differences show

The original forms `receiver + 0x30000` using LUI/ADDU and accesses signed
displacements `-2756/-2752`. GNU flat forms `receiver + 0x28000` with LUI/ORI/ADDU
and accesses positive `0x753C/0x7540`. GNU pointer forms `receiver + 0x2F53C`
with the same three-instruction pattern and accesses offsets zero/four.

Both GNU bodies put the default-value LI instructions in their two BNE delay
slots. The original has NOPs there and its constants follow the slots; the BNE
displacements are correspondingly three rather than two. The extra address
instruction adds four bytes while using those two delay slots removes eight,
reconciling 64 versus 68. This is an explanation of the observed size difference,
not a normalization or exactness rule. Registers, addresses, branch words and
all complete bytes remain part of the strict comparison.

The unchanged bounded address checker correctly returns **UNINTERPRETED** for
both GNU bodies because its branch contract supports NOP delay slots only. It
withholds reuse counts and access traces. The historical MW cases remain
interpreted with five and one static large-base sites. The checker is not
weakened to obtain a count for the new instruction form. Independent raw
instruction analysis is kept separate in `outcome-analysis.json`.

The retained object output identifies a pipeline-level difference; this bucket
does not establish which address details came from frontend emission versus
assembler expansion. Raw assembly was hashed by the inherited GNU staging path
but not retained there. Nor does this result justify changing scheduling flags
for this routine. Compiler source, assembler behavior and other global producer
versions are separate investigation questions.
