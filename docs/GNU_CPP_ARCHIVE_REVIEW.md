## Instruction observations

Both GNU functions use a single adjusted receiver base and preserve the observed
upper-then-lower stores, conditional low default, upper reload and conditional
upper default. They are distinct64-byte functions: flat-body SHA-256
`20c08726680efb40c046d0c9161b7e049e4a293894276d08e813c8e03ddd8be3`,
pointer-body SHA-256
`8fa560bd531c7e13c5d123495586a269246ea10e83f55eb97a050101f9565718`.
The reviewer checked their full retained disassemblies against the original
complete target and object bytes.

The GNU flat form builds receiver-plus-`0x28000` with LUI/ORI/ADDU and uses
positive displacements `0x753C/0x7540`. The GNU pointer form instead builds
receiver-plus-`0x2F53C` with the same three-instruction pattern and uses
displacements zero/four. The target builds receiver-plus-`0x30000` using only
LUI/ADDU and accesses signed displacements `0xF53C/0xF540`.

Both GNU conditional BNE delay slots contain the appropriate default-value LI;
the target has NOPs there and separate default-value instructions afterward.
The GNU extra base-formation instruction adds four bytes while these two filled
delay slots remove eight, accounting for64 versus68 bytes. Both retain the
return NOP. This is an instruction-count explanation, not register/address
normalization, an approximate-match score or evidence that any particular
backend pass caused the choices. The complete byte comparator remains decisive.
